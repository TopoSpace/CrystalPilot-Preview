## 0. 结论先行

1. **系统不是“AI 与晶体程序简单拼接”。** 已有真实的 Codex app-server、按项目 MCP、审批、NodeStore 分支/检出、双精修引擎、checkCIF 与交付门禁。下一轮不应首先推倒这些基础。
2. **旧 README/旧计划严重落后于代码。** 本轮实际注册 **70 个工具**；师兄要求的大部分模块已经有实现。旧能力表同时写“已实现 LCD/PLD/CShM/Systre”和“没有实现”，已经修正明显冲突并标注历史口径。
3. **真正优先级是避免错误的成功暗示。** 本轮找到并处理了：checkCIF 未知当零警报、首次结果触发前端崩溃、GooF 错误着色、氢坐标回放改变模型却沿用 R 值、交付评分只验证另一份 RES、对称相关多网被当成互穿。
4. **Astra 已实际接入，不只是改一个字符串。** 全局和旧路由模型默认切换，主推理档仍为 xhigh；26 个近期项目遗留的显式模型覆盖也迁移为 Astra，历史战役清单和已发生的记录不改。两个真实冷启动项目均通过原有 HTTP/Harness/MCP 路径运行，子代理关闭。
5. **复杂结构仍需要交互。** 小分子 CIF 可复现参考；Cage 的空间位置恢复并不等于化学身份正确，最终只能诊断性交付。最有价值的下一步是带证据的先验询问、状态一致性和假设试验，不是无上限增加精修轮数或子代理。

## 5. Harness、审批、分支与子代理

### 已经内化的部分

- 权限不是前端装饰：只读模式在 MCP 进程内拒绝非只读工具；Copilot 模式按写工具审批；自动/完全访问有不同沙箱/审批配置。
- 变更工具有自动节点提交；历史节点能检出、比较、分支；交付门禁要求验证解释和文件哈希。
- 一套 SSE/归一化事件用于实时显示与转录回放；支持中途 steer、审批卡和工具进度。
- Windows 科学扩展预热是实测修过的工程约束，不应为了“清理代码”随意移到 worker 首次导入。

### 尚未成为完整的科学事务层

- 一个节点名不能唯一解释所有数据/参数/外部作业来源；本轮 RES 缺陷证明了“R1 接近 + 原子数相同”不足以保证同一模型。
- `ProjectHandle` 的 `threading.Lock` 只属于当前 MCP 进程。多个可写进程/旧会话是否对同一项目写入，需要跨进程单写者与 revision 检查，而不是依靠流程约定。
- 阶段轨主要由工具名及 situation_report 推断，不代表经过持久裁决的科学阶段。
- 各回合、重试、follow-up、收尾的预算口径不同；原 `wall_s` 不涵盖全部实际时间。重启后的运行更不能简单用一个数与正常运行比较。
- 本轮转录出现 `reasoning/contextCompaction` 等 `item_unhandled` 元数据；不能把这些计数直接理解为“所有推理都丢了”，但应增加 SDK 协议版本/事件契约测试与明确的显示降级。

### 子代理：可用机制，不是已证明的升级方向

有两条路径：原生四角色（空间群/化学/密度/验证），以及嵌套 `consult_specialist` 五角色（加精修策略）。原生角色文件自带只读 MCP 覆盖；嵌套顾问也有只读守卫及递归限制。

当前代码 `DEFAULT_SUBAGENT_POLICY = "top_tier"`，有效 xhigh 时可注入委派提示；这与旧说明“默认关”不完全一致。关闭设置撤除角色/提示，但不应将它夸大成已经对所有 SDK 通用代理能力做了硬禁用。下一轮应统一两条入口与用户意图、成本账和能力边界。

历史 reg12：委派三次，验证顾问发现事实错误，但最终仍 below_bar；n=1、预算/模型/模板差异不能证明收益。本轮两个 Astra 项目的 `subagents=off`、转录协作事件为 0，验证了本次单主代理路径能运行；没有承诺所有未来模型都不会自行委派。

### 7.4 Cage 暴露的真实瓶颈

- 文件标称分辨率约 0.691 Å，但可重复信号支持的工作截断约 1.00 Å；不是简单以“标称高分辨率”评判模型可靠性。
- SHELXT 1.00 Å 求解第一轮无合格结果，1.25 Å 条件变化后产生粗解；表明试验条件比盲目延长同条件预算重要。
- 自动求解的 Br 标签不是真实元素证据；接近 Zr 吸收边的波长使散射强弱判断更复杂。Agent 把 Fe 作为工作假设并披露不确定，但仍未得到正确化学身份。
- 缺投料金属、配体/谱学和含卤溶剂信息；继续堆工具调用无法替代有判别力的用户输入。
- 有中断的 ghost_test 尚无裁决，恢复时没有把它当成应删原子的结论；诊断性交付保留了限制。

下一轮最有意义的实验是：同一真实样本，先固定无先验基线，再仅补入已有合成记录里的事实，比较第二轮如何改变假设和结果；不能泄露参考坐标/最终组成来做假“交互提升”。

## 11. 下一轮建议：不要先做大重写

推荐按以下顺序执行，详细设计、验收与停止条件在升级方案中：

1. **科学状态/证据一致性。** 模型、数据、掩膜、权重、引擎版本共同的指纹；验证新鲜度；精确交付/回滚。
2. **已知科学缺口。** 跨对称闭环、纯 CIF 分析、方向性孔径产品接口、客体规则与机械链接验证；每项独立答案先行。
3. **人机交互。** 根据真实分歧提问，结构和证据联动、引用回到历史现场、结果源清楚。
4. **执行韧性。** 跨进程单写者、幂等调用/取消、重试总预算、可观察的状态投影。
5. **可选子代理对照。** 关闭路径先验收；只读固定快照；父子线程完整成本；多样本配对后决定是否增加最高档位下的使用积极性。
6. **难样本/原始帧泛化。** 以数据授权、真实采集元信息和独立评估为前提，不用一颗小分子的好成绩代表复杂 MOF/Cage。

目标应是：新人能用自然语言理解已有证据、补充关键事实、看见系统试过什么、随时回到可信状态，并在解不完整时收到真正可用的诊断交付，而不是更多按钮或更漂亮的成功标签。
