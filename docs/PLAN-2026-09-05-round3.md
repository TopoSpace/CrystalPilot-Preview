# CrystalPilot 第三轮升级方案（2026-09-05 全面盘点 → R0–R7）

> 本文取代 `docs/PLAN-2026-09-05-upgrade.md` 作为下一轮的执行依据（其 A–F 的思路保留，但按本次盘点与取证证据重排、落到文件级）。面向用户的报告一律中文；代码注释/提交信息可英文。

## 0. 背景与目标（Context）

**为什么现在做这一轮。** 第二轮（R0–R7，tag `r2-r7-done`）与 09-05 第一批已经把系统做成了真正可用的工作台：70 个 MCP 工具、NodeStore 分支/检出、双精修引擎、分块分析产物、纯 CIF 项目、checkCIF 交付门禁、子代理机制。随后的 Zr-MOF＋低占有率客体实机演示（398 次调用、3 h 20 min）暴露了下一步真正的瓶颈：

1. **one-shot 解不完复杂结构时，交互决定成败**：三次人工插话分别补足了"客体存在""要整分子""允许非发表级候选"，系统自己没有整分子级工具，只能逐原子补点并靠临时 shell 脚本找到斜向路径。
2. **成功返回里藏着错误肯定**：`fit_fragment` 27 次 `ok:true` 中 15 次零新增；`solvent_mask` 6 次 true 只 1 次收敛；`audit_guest_evidence` 用满占有率分母和均值给出 SUPPORTS；顶层 `final.res` 丢 EADP/SUMP 却报 "agree"。
3. **前端在长会话下不稳**：刷新后重复/重排、假运行卡、插话退出 DOM、命令输出被尾部替换、时长单位错；没有 ErrorBoundary。
4. **师兄清单的功能大多已实现，但正确性与"随显示范围自适应"还有明确缺口**（对称闭合环、有限片段闭包、纯 CIF 无 PLD、互穿只到"对称相关"）。
5. **子代理机制可用、收益未证明**，且策略与档位（是否有 `max`）尚未统一。

**本轮目标**：让 Agent 真正需要的工具存在且诚实；让结构成为侧栏主体、grow/pack 语义与 Olex2 对齐；让长会话稳定可读；把"问人"变成流程的一部分；子代理按档位可选；每轮一格真实数据、每轮一个可回滚 tag。

### 1.6 外部参照（本次实读）

- **Olex2 官方**（`Olex2/Olex2Manual` grow/pack/compaq/mode_grow + olexsys Toolbox Work）：GUI "Growing" 三个下拉，Grow: *Grow All*(`grow`，"continue grow until the operation results in a symmetry element that has been used previously") / *Shells*(`grow -s`) / *Complete*(`grow -w`，把已用算符施加到未连接片段：溶剂/抗衡离子) / *Asym. ## 2. 架构决定（本轮不推倒内核，在应用层补四个一等对象）
