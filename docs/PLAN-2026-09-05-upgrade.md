## 1. 核心判断与本轮边界

1. **不推倒晶体学内核。** cctbx/smtbx、SHELXL、PLATON、已有 NodeStore 和 MCP 工具面已形成真正可运行的系统。主要问题是“证据、模型、数据、报告、画面是否指向同一个状态”，以及失败/未知状态会不会被当成成功。
2. **必要的架构升级集中在应用层。** 从分散的文件状态与聊天推断，逐步升级为“有版本的科学状态 + 显式假设/试验/裁决 + 有来源的分析产物 + 单写者执行队列”。不把流程硬编码成不可打断的自动流水线。
3. **先防误导，再增加能力，再打磨体验。** 本轮已经修复侧栏越界、引用身份、grow 文案、checkCIF 未知变零及动态崩溃、GooF 判读等可独立验证的问题。剩余复杂科学/事务问题按下面的门禁实施。
4. **主路径不依赖子代理。** 用户不开启仍具备完整工作流；开启只代表允许受约束的只读审计，不代表把判断外包给多数投票。
5. **GPT-6-Astra 是新的代码默认，主推理档位仍为 xhigh。** 按本次“当前模型全部切换”的要求，26 个近期项目中的旧模型运行时覆盖也已迁移，并有字段级撤销清单；未来用户仍可显式选其他模型。历史战役固定参数和已发生的历史记录没有篡改；做模型对照时另外生成冻结清单。

## 3. A：科学状态与证据一致性（第一优先）

### A1. 建立可读的状态关联

使用显式版本和科学字段，而不是文件摘要；同一 R1 不代表同一模型：

- 项目、节点、父节点/分支与单调修订号；
- 数据导入版本、来源文件、HKLF/合并方式/分辨率/删点记录；
- 元素、坐标、占有率、PART/FVAR、孪晶、权重、氢约束、溶剂掩膜及其参数；
- 引擎名称/版本、工具版本、分析判据/参数版本；
- 输入状态与输出状态、开始/结束时间、运行 ID、调用 ID。

每份观察、图、几何表、checkCIF、CIF/FCF 和截图都引用这些标识。字段暂时缺失时返回 `unknown`，不能凭当前活动节点补写旧报告的来源。

**验收：** 在一个项目内先验证 n1、再修改为 n2，n1 的报告不能显示为 n2 的有效验证；历史节点的引用能回到原节点/原子/对称像；切换反射集后旧节点仍能明确说明其数据来源和可重放条件。

### A2. 把“检查成功”与“检查没有发现问题”分开

统一分析产物状态：`not_run / running / complete / partial / unsupported / failed / stale`。工具执行成功、某项判据通过、研究问题解决、达到交付门槛，是四件不同的事。

- checkCIF 未运行、不可解析、缺计数和失败不能变成 A0/B0/C0（本轮已修）。
- 分析采用分块就绪/独立进度，不让最快的相互作用表等待最慢的孔道块。本轮真实 MOF 冷分析约130s，其中孔道约118s；这是下一轮性能基线，不应仅通过延长测试超时消除告警。
- “没有找到 π–π”必须区分：完整搜索为空、环未识别、预算截断、判据未通过。
- “无孔道”必须区分：计算完成的 0、无反射数据导致未算、掩膜失败、探针进不去。
- RCSR 未安装、求解失败、无周期网、不在数据库、多个连通分量分别命中，都应有不同状态。
- 误差类型分别标：实验 esd、网格离散尺度、采样/截断误差、经验判据；不共用一个含糊的“±”。

**验收：** 对每类分析做缺失、超时、坏数据、部分结果、空结果和缓存失效测试；UI、MCP、报告对同一产物给出相同状态。

### A3. 加强交付与重启验证

保留现有 `write_outputs → run_checkcif → finalize_delivery`，增加：

1. 所有交付文件绑定同一个有效状态，不只对账 R1。
2. CIF 与 FCF、精修器原始结果、可重启 RES 分别注明角色；检测标签/坐标/占有率/约束差异。
3. 氢原子允许合法的等价标签置换，但必须有映射；不能把有实质几何差异的 RES 冒充提交 CIF 的精确坐标副本。
4. 在干净副本中以交付 RES + 数据作 SHELXL 零轮重放，与提交 CIF/FCF 对账；不只测 CIF 中嵌入的另一份 RES。
5. 任何 waiver 都要带证据、影响和确认者；`publication` 评分标签不等于用户已经提供了全部发表信息。

**验收：** 至少覆盖无序、可旋转甲基氢、AFIX、HKLF5/孪晶和掩膜各一例；不存在“测试只读到另一份更好的文件”的假重放。

## 4. B：师兄清单与晶体学工具的下一步

### B1. 成键、环和相互作用

继续让 `chem/bonding.py` 成为共同成键来源，避免查看器、验证器、配位表又出现各自阈值。

- 优先补齐跨对称元素闭合、ASU 索引重复的环；当前显式告知遗漏比静默漏行好，但不能长期代替实际几何计算。
- π–π、C–H···π、C–H···X、卤键、阴离子–π分别扩展已知答案样本，覆盖不同空间群、非正交胞、PART、特殊位置与边界伙伴。
- 明确几何候选不等于相互作用能，也不等于化学身份已证实。
- 氢键表以 SHELXL HTAB/EQIV 输出为带 esd 的交付依据；查看器的几何表保留 H 来源和判据，不自行伪造 esd。

**验收：** 同一节点、同一判据下，MCP/分析表/显示线一致；与独立引擎及文献不一致时逐行分类原因，不以修改答案夹具来“通过”。

### B2. grow / pack 的完整语义

菜单明确分两组：

- **范围：** ASU、整分子晶胞、超胞、半径、分数坐标盒；
- **动作：** 再长一壳、完整有限片段/有界周期扩展、补齐已用对称操作、点击生长键、收回。

本轮“扩展至 4 层”是诚实的预算模式，不是最终闭包算法。下一轮增加真正的有限片段闭包；周期网用独立的终止规则和预算，不能承诺“整个 MOF 长满”。`grow -w` 保持补其他 moiety 的语义；`compaq/assemble_asu` 涉及模型变化时仍交主 Agent 与审批，不能由只读查看器直接写节点。

**验收：** 长链分子、跨多个对称操作闭合的笼、1-D/2-D/3-D 配位网分别有解析夹具；操作对当前范围生效；超胞提示中的 `pack 0 n` 与半径 `pack n` 不混淆。

### B3. 范围是所有图层共同的契约

沿用 `scene.range/tiles`，补成逐图层可核验的覆盖说明：

- 原子/键、氢键/π–π、孔道、Fo−Fc/Q 峰、对称元素、简化网都声明 requested/drawn 范围；
- 单胞标量明确“每胞”，不因超胞显示就悄悄放大；
- 边界伙伴可以在范围外，但必须解释对称操作及边界标记；
- 原子数、8 胞对称层、64 胞等值面、3000 峰等预算分别披露，不能用一块总提示掩盖某一层只画了中心部分；
- 对大范围优先做按距离/屏幕分辨率的 LOD 与分批渲染，避免只截断最远处造成“孔道不连通”的视觉误读。

**验收：** ASU、grow、cell、2³/3³/4³、半径和负分数盒逐一验证；选取非正交胞及跨胞相互作用；同时比较实际绘制包围盒、实例数和截图，而不只断言存在 canvas。

### B4. 孔道、客体与拓扑

- 孔隙率、vdW 球并集堆积指数、LCD、PLD、方向性 PLD、掩膜电子数保持独立定义。
- 增加网格收敛曲线、半径表/探针敏感性和非正交胞测试；对照 Zeo++/PLATON 时先对齐结构、H、客体、半径与探针，不直接比较不同定义的数字。
- 宿主/客体大小规则只给候选归属。多笼、盐、共晶、半个特殊位置分子和无序组分必须显式说明规则，不强行套“主客体”。
- “独立网”“对称相关的网”“实际互穿/机械互锁”分开。**本轮已先纠正输出语义：** 多网的互穿/互锁为 null/not_tested，单独给 symmetry_related，分析缓存v6。下一轮才增加真正的环穿越/链接判定；不能把已有对称映射直接冒充证明。
- 保留大环、球形度、惯量、CShM 等可验证证据；“灯笼/梨型”优先作为人类注释和解释性建议，不发布未经验证的自动分类器。

### B5. 纯 CIF 分析入口

新增不要求衍射数据的只读结构文档：可查看、grow、测几何、相互作用、拓扑、几何孔隙；明确禁止精修和假造 R1/Fo−Fc/残余电子数。将“结构文档”和“含反射数据的精修项目”分层，而不是塞入假 HKL。

**验收：** 导入已知 MOF、Cage、小分子 CIF 可完成适用分析；所有需要衍射数据的工具明确不可用；文献 R 值与本次重算值的来源标签不同。

## 5. C：自然语言协作与前端优化

### C1. 让结构持续成为主体

现有暖色主题、字号档、浮动工具分组保留，不再堆一个常驻按钮区。下一轮对真实工作流程试验：

- 结构保持可见；分析表采用可收起检查器，与所选原子/相互作用联动，而不是每次看数据都替换整个结构视口。
- 顶部只保留身份、R1/wR2/GooF、数据质量/当前节点与必要警示；详细统计可展开。
- 小屏/侧栏拖窄时，工具组和表格能滚动或换行；保留用户宽度偏好但不能让它把聊天挤到不可用。
- 截图/引用/导出不在尚未完成的新场景请求上生成错误说明。
- 数据变更、分辨率/掩膜/孪晶条件不同的两个 R1，标“不可直接比较”，不只画绿色下降箭头。

**验收：** 1100×700、1366×768、1920×1080、300px 侧栏及更窄窗口/放大字号；两主题、键盘、减少动效模式；确认没有遮住关键按钮、焦点丢失或静态截图之外的崩溃。

### C2. 动效与长会话

借鉴 DeepSeek 的过程折叠和滚动锚、Claude Code 的稳定长对话渲染、Codex 的任务/权限边界：

- 同时只保留一个主工作状态；当前工具/等待审批/等待数据/失败/完成明确不同。
- 阶段摘要由有来源的事件驱动；调用过某个工具，不等于之前所有科学阶段都完成。
- 完成后折叠重复过程；错误、拒绝、用户插话和未解决判断不能被藏进成功摘要。
- 使用窗口化/增量投影减少长日志重算；用户阅读历史时不强制跳回底部。
- 动效只做轻量状态提示，支持 reduced-motion；不是虚假的百分比进度条。

### C3. 把“问人”变成科学流程的一部分

在缺少关键信息时提供一张简洁的问题卡，而非泛泛“需要更多信息”：

1. 已确定什么；
2. 哪些假设仍有分歧，各有什么证据；
3. 只询问会改变下一步的一项事实，例如投料金属、含卤溶剂、化学式/谱学、样品处理或孪晶线索；
4. 用户不知道时，提供“保守继续/诊断性交付”的可行路径。

不会因用户说了一个答案就硬改模型；用户信息标为先验，由主 Agent 通过数值与化学证据验证。用同一样本的“首轮缺先验→补充真实投料信息→有界二轮”实验衡量交互收益，禁止把参考坐标/最终组成偷喂给模型。

### C4. 引用继续做核心交互

保留并扩展当前引用：项目/节点、原子标签、对称像、峰坐标/高度、测量值/单位、判据版本、图层范围及数据来源。引用应该支持回到历史现场，并明确这是历史值；不默认改动当前模型。

## 6. D：MCP 与 Harness 的应用层升级

### D1. 工具质量优先于数量

在现有约 70 个工具上先统一：

- 参数单位、枚举、最小示例、能力前提和常见恢复方式；
- 未知参数/不支持方法返回结构化错误及合法选项，减少 schema 猜测；
- 观察类输出分页与摘要，完整结果留本地产物；
- 每次调用标明只读、试验副本、提交修改或外部上传；
- 工具卡与注册表/权限表仍由测试锁定，避免出现“后端新工具没有前端语义”。

新增工具只在存在明确的闭环缺口时引入，例如纯 CIF 分析、方向性孔径、对称闭合环、独立假设试验。不要为已有函数再包同义入口，制造选择负担。

### D2. 单写者、事务与可取消计算

把重计算与 Web/SSE 服务进一步隔离：一个项目的模型写入串行；只读分析引用不可变快照；分析失败不能污染活动节点。

- 修改操作带 `expected_revision`，审批期间模型已经变更则重新评估，不把旧审批用于新状态。
- 调用 ID 支持幂等；重连/重试前先确认上次操作是否已经提交。
- 长任务有心跳、取消协议、最终状态和资源回收；取消不是仅结束聊天流。
- 重试、follow-up、收尾共享一个可解释的总体预算，同时保留有限的安全交付尾部时间。
- `wall_s`、主任务耗时、收尾、评分、子代理与重试分别记账，不把部分阶段当全过程。

### D3. 用适配层渐进迁移

先统一 `Observation/AnalysisProduct/DeliveryManifest` 与节点/修订来源，再把隐式跨文件动作移入应用服务。MCP、HTTP、UI 消费同一个应用服务契约；保留旧工具名和事件回放兼容层。

只有在实测证明 JSONL/目录扫描已经成为瓶颈时，再引入索引存储（例如 SQLite/WAL）；科学文件仍保留可读、可审计的原始产物。没有证据支持现在同时重写渲染器、数值引擎和存储层。

## 7. E：可选子代理，不以“数量多”冒充效果好

### E1. 先统一开关和能力边界

当前原生角色与嵌套 `consult_specialist` 是两条路径。下一轮统一用户可见策略、日志、预算和结果 schema，保留兼容入口。核实并消除“文档说默认关，但有效 xhigh 下默认策略允许委派”的歧义。

建议新项目明确 opt-in；关闭时模板、原生能力、嵌套顾问和 UI 状态要一致。SDK 当前公开的最高档位为 xhigh；未核实支持 max 之前，不在 UI 造一个实际无效的 max 档。未来支持 max 后，可在用户已开启的前提下增加建议委派的积极程度。

### E2. 适合的角色

- 空间群：对候选及反证独立审阅；
- 化学建模：元素/连接/电荷/投料一致性；
- 精修策略：建议可检验试验，不直接提交模型；
- 残余密度：复核峰、掩膜与客体证据；
- 验证/交付：独立检查声明、CIF、checkCIF 和未解决列表。

所有角色看到固定节点的证据包；默认只读、禁止递归，主 Agent 是唯一模型写者和最终裁决者。结果包括证据 ID、相互矛盾的事实、建议试验、风险与不确定性；不得用投票或置信度形容词代替验证。

### E3. 收益对照

先以相同 Astra/xhigh、工具版本、输入、先验和预算做关闭/开启的配对实验。样本覆盖小分子、MOF、Cage、无序/孪晶，不把单格 reg12 当统计结论。

指标：结构/元素正确率、错误事实漏检、checkCIF/交付一致性、有效与重复试验数、真正需要人补充的事项、总耗时和父子线程完整 token 账。先规定扩围门槛，再看结果；收益未证明就保持可选，不让低档/关闭路径退化。

## 8. F：真实数据验收矩阵

| 层 | 数据 | 验证目标 |
|---|---|---|
| 解析/不变量 | 合成的周期、特殊位置、PART、已知形状 | 数学定义、单位、对称/平移/原点/原子顺序不变性 |
| 独立已知答案 | MOF-5、HKUST-1、ZIF-8、UiO-66、互穿样本、氢键/卤键样本 | Systre/PLATON/Zeo++/文献对照，逐条解释差异 |
| 导入/回滚/交付 | 原始 SHELX、CIF、HKLF5、AFIX、mask、weights | 零轮复现、跨引擎、状态恢复、科学字段与交付版本对应 |
| 真实浏览器 | 真实节点树和分析产物 | 两主题、多尺寸、菜单、选择/引用、grow/超胞、动态结果、错误/权限状态 |
| Agent 端到端 | 小分子 + MOF + Cage + 难无序/孪晶 | 科学正确与诚实交付，不以低 R 或 UI 跑通充当解出结构 |
| 人机交互 | 同样本逐轮补充真实先验 | 是否减少错误分支、提出更有效问题、在预算内收敛 |
| 原始帧 | 已有小分子帧 + 经授权的复杂 MOF/Cage 帧 | 实际几何模型、吸收/缩放、孪晶、多晶格与减数失败可诊断 |

每格记录：输入来源/版本/模型/effort/子代理策略、预算及并发负载、只读输入与工作副本路径、实际工具结果、独立评分、截图/链接与失败。端到端成本昂贵：确定性验证先行，再跑有判别力的真实格子；不同预算、先验或参考类型的运行不能直接横比胜率。

## 9. 版本管理与交付纪律

- 软件代码的 Git 回滚，与晶体项目的 NodeStore 分支/checkout 是两层，不可混用。
- 本轮开始基线为 `c84a7b47d21f`；模型、侧栏/引用、验证/指标修复分别保存为独立提交，详见盘点报告。
- 不改原始数据；项目与战役继续置于仓库外；测试使用明确挑选的工作副本，结果回到实际晶体学量核对。
- 不提交凭据、原始衍射数据、受限二进制或整段未脱敏日志；外部 checkCIF 上传继续显式 opt-in 和逐次审批。

- 每轮说明“修好了什么、验证了什么、还没实现/没验证什么”；不能把报告末尾的后续计划写成已完成能力。
