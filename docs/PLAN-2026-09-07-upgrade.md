## 0. 先做与不做

**本轮已经做了**：三套深浅主题、远雾/裁切控制、对称/Q 峰覆盖提示、结构/截图引用锚、阶段“已进行≠已完成”的修复。下一轮先用真实使用反馈微调，不马上再换一套 UI。

**保留**：cctbx/smtbx/SHELXL/PLATON、现有 NodeStore 和 MCP 名称、引用机制、单主 Agent 路径、独立 CODEX_HOME、按项目审批及中途插话。

**暂不做**：全盘换渲染器/状态库/数据库；引入默认必须使用的子代理；制造假进度百分比；根据几何近似自动宣布机械互锁/“梨型笼”；为了追 R 删除数据或修改参考答案。

## 2. R0：先消除“主安装可用、新工作树不可复现”

### 工作包

1. **资源清单和预检**：项目 Python、SDK、实际 Codex binary、SHELXL/SHELXT/PLATON、Systre/Java、可选 DIALS/Olex2、知识模板、模型目录逐项报告“可用/缺失/版本不同”。不得用“进程存在”代替“监听和 API 正常”。
2. **路径去硬编码**：运行配置不要把另一个检出的 `.venv`、脚本、model catalog 写死在当前工作树。只从 CrystalPilot 的显式配置或该 worktree 根解析，绝不探测/覆盖个人 `~\.codex`。
3. **部署清单**：源码版本、前端构建时间、Python/内核路径、端口、CPU 限额、隔离 CODEX_HOME、外部二进制来源、数据所在目录。密钥只验证是否可用，不打印内容。
4. **恢复输入纪律**：现有 ignored 战役数据通过授权白名单复制到新外部项目；不能让测试因只有 RES 没有 HKL 而产生假失败，更不能静默跳过全部真实数据后声称验收完成。
5. **提供方设置**：保留 gateway 与 OpenRouter，按 [提供方配置设计](PROVIDERS-2026-09-07.md) 分开协议、认证、模型元数据和验证层；修复 UI 保存裸密钥与 auth hook 解析不一致，其他协议不得伪装为 Codex 原生支持。
6. **模型入口**：使用 `scripts\run_live.py` 明确 `--provider crystalpilot --model gpt-5.6-sol --effort xhigh --subagents off --base http://127.0.0.1:8010/api`。先验证隔离 gateway 认证，再跑解析；不改用 OpenRouter 或个人 Codex。

### 首个真实基线

- 一个普通小分子：不选本轮无法复现的电荷密度研究作为“最容易成功”的展示样本。
- 一个 MOF：有匹配的原始 HKL/INS、掩膜/无序约定，来源清楚。
- 一个 Cage：复杂元素/低占有率客体；保留“缺先验→真实问题→补充事实”的两轮过程。
- 每次只跑一个昂贵解析格；打印完整浏览器线程链接，记录时限、模型、实际档位、权限和子代理设置。

**验收**：同版本干净副本能打开、计算、恢复；记录真实调用而非只改模型字符串。缺凭据/缺数据属于 blocked，不是通过。先把本轮 NU-1000/对乙酰氨基酚 R 值差异列为待解剖案例，而非擅自替换其 SF 定义。NU-1000 的本地 checkCIF 在 90 秒和默认 420 秒均未生成 `.chk`，也列为 R0 的必须排障项；不能只延长超时、隐去失败或用接触表测试代替完整验证。

涉及：`scripts\run_live.py`、`scripts\restart_server.ps1`、`workbench\kernel.py/model_catalog.py/core.py/providers.py`、健康与关于页。

## 3. R1：应用层的必要架构升级

### 3.1 一个项目只有一个写者

当前初始化锁和进程内 MCP 锁分别解决不同问题。下一步引入项目级应用服务：

- 写操作先取得跨进程租约/锁，恢复和提交都校验同一项目修订；有超时和持有者身份，不随便删别人的锁。
- 请求携带 `expected_revision`；审批等待期间若状态变化，必须重新比较影响，而非让旧审批修改新节点。
- 调用 ID 和提交结果关联：重连/重试先查询上次是否已经提交，避免一次操作变成两个节点。
- 生成输出先写暂存目录，成功后发布节点和活动引用；失败、中断或取消保留可诊断临时结果但不切 active。
- 只读分析从不可变节点/数据快照读取；主 Agent 是唯一持久模型写者，专家不共用可变 session。

**必须新增的回归**：两个独立 MCP 进程争写同项目、审批期间切节点、重试同 call、提交前进程退出、旧分析到达晚于新节点、取消后不再发布成功。失败要么不变，要么明确只有一次原子提交。

### 3.2 数据版本不只是“当前 crystal.hkl”

保存可读的 data revision、原始输入名、HKLF/合并/分辨率/SHEL/OMIT/孪晶批次/掩膜条件。每个模型节点说明使用哪个数据版本；更换 HKL 后历史节点不能自动引用新反射集产生的指标。

`NodeState`、`Observation`、`AnalysisProduct`、`ValidationReport`、`Delivery` 都引用：项目、节点、模型修订、数据修订、工具/引擎及参数版本。没有来源就明确 unknown，不替历史记录补造“当前来源”。采用语义与行为复验，不把文件摘要检查当作科学正确性的替代。

### 3.3 指标比较的前提

R1/wR2/GooF、残峰、掩膜电子数对比必须说明同一反射范围、数据处理、孪晶和掩膜条件。若不同，显示简短“条件不同”，展开后才展示差别；不能仅凭 R1 下降给绿箭头。

**架构迁移方式**：先在现有 JSON 节点/产物上加兼容字段，再让 MCP/HTTP/UI 消费共同应用服务；旧节点仍可读，缺字段 unknown。只有实测证明目录扫描/JSONL 成瓶颈后再引入 SQLite/WAL 索引，不同步更换数值引擎和文件格式。

## 4. R2：前端作为重点，不再堆砌

### 4.1 视觉层级

- **第一层**：晶体、空间群、当前节点身份、R1/wR2/GooF、必要风险。保留原子元素颜色独立于主题。
- **第二层**：当前选择、配位、孔道/接触几何、单项验证证据，放在可收起检查器里。
- **第三层**：绘制/关系/证据/视图控制，继续放现有浮层和键盘入口，不新增常驻按钮墙。
- **第四层**：技术参数、对称操作全文、原始输出/日志。默认折叠；错误、未解问题和等待人工不能藏入“成功摘要”。

桌面保留“项目，对话，结构”；聚焦模式结构至少约六成宽。窄窗按任务切换而不是把三栏硬塞进去。分析时结构保持可见，但表格与结构比例可调，避免结构虽存在却小到无法使用。

### 4.2 关键具体改造

1. **统一检查器**：点原子/峰/π–π/孔区域，表格自动定位；表格行反向高亮结构。选择身份包括节点、ASU 原子、对称操作和晶胞平移，不用临时绘制编号。
2. **比较模式**：首版同步相机并排“当前/父节点”，共享选择与显隐；同时列条件差别、R/几何/残密度变化。先做好一个确定的比较，不另造通用多窗管理器。
3. **节点/交付**：诊断分支可折叠，最终和候选清楚分组；文件按结构/验证/数据分类；长路径留悬停和复制，不能铺成芯片墙。
4. **按钮及字体**：用户级字号 13–16 保留；主要阅读默认评估 15px，但不擅自覆盖旧偏好。对 11px 以下硬编码、透明文本/警报/分数和数学符号专项检查；AA token 测试外再测实际 DOM 组合。
5. **工作动效**：一条主状态；轻量呼吸/渐变只用于当前工作，不整卡扫光。长计算显示真实工具、用时和心跳，不制造百分比；等待审批/用户/网络断开独立状态。
6. **减少动效完整闭环**：除了 CSS，还让 smooth scroll、自动居中和显式旋转遵从用户/系统偏好；不能只停 shimmer。后台页面减少计时刷新和渲染，恢复时不丢状态。
7. **键盘**：所有“引用”、弹层、滑块、页签可键盘操作；Esc 只关最上层；焦点回到触发按钮。消除嵌套交互元素，Space/Enter 行为一致。
8. **引用**：本批 anchor 已补齐；下一步保存可读视图状态（节点、范围、相机、层、截断），点击历史引用应恢复历史现场或明确不可恢复，不悄悄 checkout 当前科学模型。

### 4.3 主题原则

继续提供 Anthropic/OpenAI/Kimi 风格参考，每套浅/深；主色只用于选中、当前动作和少量强调。警报级别色、元素色、残密度正负色固定语义。设置不显示“高级感/AI 原生/革命性”等开发宣传词。

完整命令、科学限定和恢复说明尽量放悬停、详情、帮助或工具输出。短标签仍应有意义，如“逐层生长”“补齐片段”“前后裁切”，不能为了极简只剩无法理解的图标。

### 验收矩阵

390×720、900×650、1100×700、1366×768、1920×1080；三色板×浅深；13/15/16px；结构/分析/验证/节点页；菜单展开、选择/引用、开始/停止/失败/重连；系统 reduced-motion、键盘、200% 缩放。真实 MOF/Cage/小分子各至少一例，不仅拍空白欢迎页。

## 5. R3：统一范围与科学验证

### 5.1 显示范围契约

在 `scene.range` 之上，每层返回/计算：`requested_extent`、`drawn_extent`、实例数、被截断部分、预算、是否包括边界伙伴。原子、键、相互作用、孔道、密度、峰、对称和简化网共用范围，不各自猜测包围盒。

- 单胞标量继续标“每胞”。
- 4×4×4、负分数盒、半径范围、非正交胞、Grow All 周期截断分别验收。
- 不把“只画了最中心 8 胞对称元素”描述为全范围；本轮已修该提示，后续统一到所有图层。
- 图层结果与范围切换竞态时，保留上个完整场景并显示加载，不把旧关系线放在新节点上。

### 5.2 性能路线

先测冷/热场景请求、分析各阶段用时、主线程长任务、首帧、交互帧时、GPU/内存峰值、取消延迟。软件渲染器和真实 GPU 分开记；缓存命中不能算算法提速。

优化顺序：分析 Worker 进程隔离/可取消 → 大几何批处理与实例化 → 有界 LRU/体素与图层 LOD → 长对话增量投影/虚拟化。保留高质量导出模式，但不让导出取消实时查看器的安全预算。未证明 3Dmol 是主要瓶颈前，不替换渲染器。

### 5.3 独立计算验证

| 项目 | 下一轮新增已知答案/反例 |
|---|---|
| grow | 特殊位置有限分子、跨多个操作的笼、1D/2D/3D 周期网；与目标 Olex2 版本逐操作对照 |
| 相互作用 | 非正交胞、周期闭环、PART、不完整 H、8 元/稠环；对齐 PLATON/SHELXL 的定义与 H 模型后逐行对照 |
| 孔道 | 同结构同探针/半径/客体规则的 Zeo++/PLATON 对照；网格收敛/沿轴与斜向通路；空值/闭腔/预算不充分的反例 |
| 客体位置 | 特殊位置半分子、多个相邻笼、配位客体、盐/共晶和跨区域；不以单一质心规则过度断言 |
| 互穿/互锁 | 环扇面双穿越、非平面环、收缩引入伪窗口、两条无环螺旋、有限索烃；必要时引入严格链接/周期同调判据，先区分“环穿越证据”与“拓扑证明” |
| 配位/形状 | 统一 CN 口径、η 配位、高 CN 7/8 独立参考；只在适用域返回 CShM |
| 导入/交付 | AFIX 甲基、FVAR/PART、EADP/EXYZ/SUMP、HKLF5、mask/反常散射；真正 final.res 零轮及有约束精修重放，不只读取 CIF 中另一份嵌入 RES |

不通过时先保存反例和原因；不要修改夹具答案迁就实现。UI/MCP/导出对同一产物的 unknown/partial/failed 必须一致。

## 6. R4：用人机交互解决 one-shot 瓶颈

现有 `investigation`、trial ledger、`ask` 卡、steer 回执继续使用，不再另造一套“智能工作流”。

每次卡住：

1. 主 Agent 汇总已经确定的事实、仍有歧义的假设和已经失败的试验。
2. 选择**一项会改变下一步**的真实问题，例如投料金属、含卤溶剂、配体身份或是否预期客体；不用“请提供更多信息”的空泛提问。
3. 用户答案记录为来源明确的先验，不能直接当实验事实修改模型；不知道时提供保守继续/诊断交付路径。
4. 候选在隔离节点试验，用同数据条件比较化学、几何、残密度、权重、R 和 checkCIF，不按单一 R 排名。
5. 到预算上限，显式区分“工具没执行完”“假设被否决”“数据不支持”“缺事实”“可交付但未定稿”。

**实验**：相同初始数据和预算，分别运行首轮缺先验、补一项实际合成记录的第二轮；不喂参考坐标/最终组成。记录问人次数、问题是否改变决策、有效/重复试验数、结构与元素正确率、未解事项、总时间/费用。

## 7. R5：子代理只作为可选专家审阅

### 当前事实

产品设置已为 `auto/on/off`：auto 参考模型档位的最顶一档，on/off 是显式选择；旧 top_tier/aggressive 兼容映射。gateway 后备档位含 xhigh/max/ultra，但模型元数据可能不同；不能把“所有 max 都更积极”写成未经探针的硬规则。本轮真实只读诊断固定 gateway Sol/xhigh/off，四次 MCP 调用成功；未进行子代理开/关收益对照。

### 适合的委派

- 空间群：候选及反证审阅。
- 化学：元素/配体/电荷/合成先验一致性。
- 精修：提出有界、可验证策略，不直接改主节点。
- 残密度：区分客体/无序/噪声证据。
- 验证：审查声明、CIF、警报解释和交付一致性。

**约束**：固定节点+数据版本证据包，只读工具、禁止递归、有限预算；输出可引用证据和建议试验，主 Agent 裁决，不以投票决定晶体学事实。专家自身失败不能让主路径不可用。

### 配对收益门槛

相同 Sol/xhigh、相同数据/先验/内核和总预算比较 off/on；至少小分子、MOF、Cage，再扩无序/孪晶。费用统计包含主线程、专家、重试和收尾。先定义可接受耗时增长与事实漏检/结构成功的收益，再看结果；没有收益不扩大默认开启。实现用到的维护子会话与产品内子代理实验是两回事，不混计。

## 8. R6：真实难样本与交付规范

- 基础：普通小分子，验证导入保真、氢、零轮重放、CIF/FCF/RES 一致性。
- MOF：大胞、溶剂掩膜、斜向孔道、配位缺陷与大图层负载。
- Cage：金属/配体身份歧义、低占有率客体、特殊位置与完整分子构建。
- 无序/孪晶：PART/FVAR、3+ 位点、HKLF5 与原始批次语义。
- 原始帧：先选已有可复现实验，再增加真实仪器元数据齐全的 MOF 帧；不凭驱动存在就宣布所有设备支持。

每格交付：浏览器 URL、输入来源/副本路径、模型/提供方/档位、依赖版本、真实事件记录、节点树、指标与适用条件、交付文件、checkCIF 执行状态与 A/B/C 解释、独立评价、未解事项、CPU/内存/时间/成本。运行时失败和未运行结果不得展示成零警报。

## 9. 发布与回滚纪律

- 软件、配置、依赖、数据和科学节点分别版本化；每轮提交明确修改哪一层。
- 发布前确认没有活动模型写任务，构建 UI，核对 8010 的实际服务路径和健康接口，再打开一个真实项目点测。
- 不让新 UI 搭旧 MCP、或新内核搭未经验证的模型目录；SDK 和 kernel 升级单独一批。
- 每批保留源码提交与简短迁移/撤销说明；回滚用逆序 revert，不覆盖用户的其他工作，不改个人 Codex。
- 任何写事务失真、报告错绑、计算无法解释、预算导致进程崩溃都触发停止条件；先修本批，再开下一批。

**下一次最值得开始的具体组合**：完成 R0 的独立 gateway 与难样本基线；并行推进 R1 单写者/数据版本，以及 R2 结构，分析检查器联动。不要先把已经齐全的工具菜单再扩一轮。
