## 1. 结论

1. **晶体学工具已经内化到 Harness，问题不是工具数量少。** 本轮实际打开结构项目得到 **74 个注册工具**。已有真实 Codex app-server、MCP 守卫、节点提交/检出、双精修引擎、分层工具结果、试验账本、研究目标、验证来源与交付流程。
2. **9 月 5 日的许多“下一步”已经实现。** 完整有限片段生长、周期闭环、沿轴 PLD、环穿越检测、整片段姿态搜索、问题卡、引用芯片、事件分页等都已进入当前代码。不能再依据旧文档判断它们缺失。
3. **前端仍有可直接改进的地方。** 本批已增加三套可选深浅主题、修复默认远雾及前后裁切、披露独立图层预算、补全结构/截图引用锚，并去掉阶段轨的虚假完成暗示。不是重新堆一层按钮。
4. **科学正确性比“工具返回成功”更严格。** 本轮真实 NU-1000 与对乙酰氨基酚的导入、SHELXL 和回滚工具链运行成功，但没有复现文献 R 值。它们只能作为诊断性复验，不能包装成已解出或发表级。
5. **下一轮最重要的架构工作是项目级写事务和数据版本，而非推倒数值内核。** 现有进程内锁、原子文件替换和初始化锁，不能直接等同于所有可写进程共享的科学事务。
6. **用户不开子代理仍是完整路径。** 当前产品已统一为 `auto/on/off`；是否改善解析质量仍需同模型、同预算配对实验。历史 GLM 小样本结果不证明 Sol 上的收益。

### 所有图层是否随范围扩展

当前不是“一切只画一胞”：孔道、密度、峰、简化网、对称元素复用 `scene.range.tiles`；相互作用在显示实例及搜索光环中计算。查看器与科学分析不是各算一套空间关系。

但存在**有意的资源预算**：原子最多 20000、场景 tiles 最多 64、对称层最多 8 胞、Q 峰最多 3000 个球、椭球约 1500 原子预算。不能撤掉上限换取“无限显示”，否则可能拖垮整个系统。

本批新增对称/Q 峰各自的“实际/请求”提示，并修复单胞峰数大于 3000 时仍超预算的问题。孔道体积、电子数仍按**每胞**，不因 2×2×2 画面而擅自乘八。后续还需逐图层覆盖对象、LOD、取消和 GPU 预算。

## 5. grow 的官方语义与产品决策

| Olex2 操作 | 正确理解 | CrystalPilot 对齐方式 |
|---|---|---|
| `fuse` / Asym. Unit | 移除显示中的对称复制，回到 ASU | 只改视图，不删除精修原子 |
| `grow` / Grow All | 扩展缺失且连通的对称等价原子 | 已有有限片段闭包与周期重复终止；保留周期/预算截断提示 |
| `grow -s` / Shells | 从当前显示逐壳扩展 | 层数是有界显示状态，不是求解进度 |
| `grow -w` / Complete | 将已经用于主片段的对称操作也用于其他 ASU 片段 | 补相应溶剂/反离子，不是任意邻域搜索 |
| `grow -b` | 完成当前显示的 growing bonds | 不与 `grow -w` 的 Complete 混同 |
| `mode grow -s` | 交互短接触方向 | 此处 `-s` 与普通 `grow -s` 不同；不能仅用同名按钮混用 |
| `pack 0 1` / `pack 0 n` | 三轴范围复制 | 范围与分子完整性分开；不要将半径 `pack n` 与超胞混淆 |
| `compaq` | ASU 内原子/片段重新排列 | 可能改变模型，应走主 Agent、审批和节点，而不是伪装为只读视图切换 |

Olex2 的命令参考与任务说明对聚合物 Grow All 有不同表述，且未标清版本。我们可以对齐语义，但**本轮没有启动 Olex2 GUI 做目标版本逐操作对照**，不承诺像素或全部行为完全相同。
