# hex / cage 两套测试数据的采集质量核定（2026-09-04）

问题：给 CrystalPilot 的 hex（staging `r25a` = 034A1，NU-1000 后修饰对溴苯乙酸）和 cage（staging `pa1c` = ZJJ1174A1，Zr₆ 笼）两套数据，在实验采集层面本身是好数据还是差数据？

方法：对两份 HKLF4 文件独立重算分壳合并统计（`iotbx.merging_statistics`，脚本 `workdir/data_quality_hex_cage.py`，只读），并与参考 CIF 里报告的采集统计对照。我们手里只有 hkl，没有衍射帧，所以"采集质量"只能从合并后的强度统计反推：冗余度、完整度、R_merge / R_pim、⟨I/σ⟩ 随分辨率的衰减、CC½、可观测反射比例。

## 1. 结论先说

两套数据都不是"高分辩率好数据"——它们的信息都在 1.2 Å 以内，1.0 Å 以外的测量基本是噪声（两份文件里 40% 以上的原始测量是负强度，就是探测器把 0.69 Å 以内的空壳也记录下来了）。这是大孔 MOF / 笼状分子在室温（参考 CIF 均写 293 K）、孔道里满是无序溶剂时的典型面貌：低角衍射强而干净，高角迅速消失。**hex 明显好于 cage**：冗余 30 对 6、完整度 100% 对 99%（到 1 Å）、1 Å 处可观测比例 44% 对 31%。

## 2. 对做结构意味着什么

- **hex**：1 Å 截断下 4437 个独立反射、1969 个可观测；人工定稿（参考 CIF）截到约 1.07–1.10 Å、3346 个反射、R1 0.1162、177 参数 + 68 限制。CrystalPilot 在同一截断附近做到 0.0833（ka1）/ 0.0858（reg2）并带收敛掩膜，说明**这套数据支持 R1 ≈ 0.08 的骨架 + 掩膜模型**，也说明参考 CIF 的 0.116 不是数据上限而是建模选择（人工把孔道里的对溴苯乙酸建了出来，掩膜没用满）。对 hex 来说，0.13 的 R1（reg1）确实是工具问题，不是数据问题，这一点和 §5.1 的掩膜互换实验互相印证。
- **cage**：全分辨率 44 942 个独立反射里只有 6794 个 I>2σ（参考 CIF 报 7044，Rint 0.4985、Rσ 0.313，与我们重算的 R_merge 0.499 完全一致，确认是同一份数据）。参考解 1175 个参数对 ~7000 个可观测反射，可观测数据/参数比只有 6；参考解自己 R1 0.1395、wR2 0.4735、GooF 0.842（权重已经过拟合）。**这套数据不支持任何模型把 R1 做到 0.10 以下**；agent 的 0.157（掩膜 + 显式客体）、ka1 的 0.164 和参考的 0.140 都落在这份数据的噪声带里。cage 格评 below_bar 的主因是数据，不是（或主要不是）工具或判断，它更适合用来考"知道何时停、如实披露"，而不是考 R1。
- 两个 agent 都把截断放在 1.0 Å（CC½ ≈ 0.35–0.46，⟨I/σ⟩ ≈ 0.4–0.6 的最后一壳）。按 I/σ ≥ 2 的老标准应截到 1.18 Å，按 CC½ ≥ 0.5 约 1.05 Å；1.0 Å 是 CC½ > 0.3 意义上的"偏乐观但可辩护"的选择，`estimate_resolution` 给的 0.996/0.997 就是这个口径。

## 5. 对后续测试设计的含义

1. cage 格的 R1 门槛应按数据定：这份数据上 0.14–0.16 已经是"能做到的"。对 cage 更有意义的考点是披露质量（unresolved 是否属实）、是否停止往噪声里加原子、是否用了与参考一致的骨架，reg2 在这几点上是合格的。
2. 需要一套**采集质量好**的 MOF 数据来考"工具与判断能否把好数据做到 R1 < 0.05"；目前数据目录（`H:/CrystalPilotData/DATA-CATALOG.md`）里更接近这个标准的是 `74609-nai.cif`（R1 0.0533，I4₁/amd）和 `cage-Zr.cif`（R1 0.0949）一类；目录标注它们带内嵌 hkl（21 968 / 425 745 条），还要核对那是未合并的原始强度还是已合并的 fcf 式列表。
3. 两套数据都是室温同步辐射采集，孔道溶剂无序是主要信息损失来源；低温采集或活化后的样品会好得多。这是给数据所有者的采集建议，不是 CrystalPilot 能补的。
