## 1. 打开系统

1. 浏览器打开 <http://127.0.0.1:8010>（服务器现在已在运行）。
2. 电脑重启后服务器不会自己起来。启动/重启只有一种被认可的方式（在 `H:\CrystalPilot` 下）：

   ```bash
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/restart_server.ps1
   ```

   约 30–80 s 后打印 `server up`；日志在 `workdir\uvicorn_r13.log` / `uvicorn_r13.err.log`。
   健康检查：<http://127.0.0.1:8010/api/health>（返回 `"ok": true`）。
3. 服务器以 4 核 + 低优先级运行（`CRYSTALPILOT_CPU_CORES=4`）；晶体学工具子进程继承同样的上限。
4. 「设置」里有「外观」（跟随系统/浅色/深色）与「字号」；「前端构建」若显示"已过期"，说明 UI 源码比构建新，需要 `cd ui && npm run build`。

## 2. 界面布局与各处含义

### 2.1 左栏（项目与对话）
- **新对话**：在当前项目里开一个新线程（模型/提供方在线程开始时固定）。
- **项目 / 最近项目**：点击切换；条目上有「改名」（写进项目设置的显示名）、「隐藏」（移到「更多」，只影响本浏览器）。
- **打开项目**：弹出对话框，两种打开方式：
  - **项目文件夹**：填本机完整路径（放在程序仓库之外，例如 `H:\CrystalPilot-campaigns\mine\test1`）；不存在会自动新建空文件夹。文件夹里应有：一个 `*.hkl`（建议叫 `crystal.hkl`）、`start.ins` 或 `start.res`（可以是 SHELXT 指令式、没有原子）、可选 `context.json`（合成先验）。
  - **仅查看 CIF**：选一个 CIF、填新项目路径 →「导入查看」。无需 HKL，只做几何/堆积分析；权限自动设为只读、子代理关；不计算精修指标、差值密度或残余电子数。
- **项目现状板**：节点数、交付数、最好 R1、A 级警报数，「刷新」重读。

### 2.2 中栏（对话）
- 顶部 **阶段轨**：数据 → 定群 → 求解 → 建模 → 精修 → 验证 → 交付；右侧一行显示当前动作 / 已用时 / 可插话 / 等待批准 / 空闲。
- **简洁 / 详细** 切换：简洁只看结论与工具行；详细展开命令、输出、思考摘要、自动审批。
- 对话里会出现：
  - 用户消息、Agent 中文说明；
  - **工具行**（✓ 完成 / ✕ 失败 / 运行中；展开看参数、结果、节点变化）。「无变化」「未定论」「证据相反」「超时 · 部分结果」是工具的诚实状态，不是成功；
    - **「未收到结果」**（2026-09-16 起）：回合已经结束，但这一行始终没有收到内核的完成事件，不是成功，也不是还在跑；展开「原始事件」能看到它到底收到了哪几条。回合被停止或失败时，未完成的行标「已中断」。以前这种行会永远转圈，根因是命令输出/完成事件按"最新一张卡"配对，同一回合里并行的两条命令会把第一条永远留在运行中；现在按内核给的 item_id 配对；
  - **审批卡**（批准 / 拒绝 / 本次会话总是允许；卡上写做什么、为什么、风险、涉及文件）；
  - **提问卡「需要你决定」**（已确定 / 分歧 / 问题 / 不知道时；点选项或「自己回答」，你的回答作为先验交给 Agent 用数据验证）；
  - **交付摘要卡**（状态：定稿 / 暂定 / 诊断性；R1/wR2/GooF；A/B/C 计数；主文件 + 「全部 N 个文件 → 产物页签」）；
  - **回合收束行**（用时、节点范围、R1 变化、工具次数）；已完成回合的过程可折叠。
  - **后台求解行**（2026-09-18 起）：Agent 用 `run_shelxt(detach=true)` 把 SHELXT 放到后台后，对话里会出现一条居中的小字行，如「SHELXT 后台求解 · 空间群搜索 · 已 5 分 12 秒（声明了重原子，SHELXT 逐个评估 Laue 类内全部空间群，此阶段不输出任何内容；本项目先前同类搜索约 13 分）」，每 15 秒原地更新；**回合结束或被你停止后它照样更新**，状态轨也会显示「回合已结束，后台仍在求解」而不是「空闲」。求解完成后这一行改为「已完成（用时、最佳 CFOM、评估了几个空间群） · 尚未采用，新回合里让 Agent 执行 `run_shelxt(from_job='job_…')` 即可采用」；采用后改为「结果已采用 → 节点 nXXXX」。刷新页面、甚至重启服务器再打开项目，已完成未采用的解仍会显示出来。
- 「回到最新」药丸：上滚后出现；「显示更早」按服务器分页加载历史。
- **连接状态**（2026-09-16 起）：中栏顶部平时不显示任何东西；实时通道一断就出现横幅，「正在重新连接…」（浏览器自己在重试）或「连接已断开，稍后自动重试」（服务器拒绝了、或 45 秒没有任何心跳）。页面会自己接回来：切回这个标签页、网络恢复、以及每 10 秒一次的看门狗都会核对一次服务器上的最新进度，有落差就整段重拉，不必刷新。以前的现象"页面停住不动，刷新才好"来自三处根因：服务器重启后 EventSource 收到非 2xx 就永久放弃；项目闲置 30 分钟被回收时旧通道悄悄断开、浏览器无从得知；以及没有任何心跳检测。
- **输入框**：Enter 发送、Shift+Enter 换行；回合运行中发送键变成「插话」（送达后有回执：已记录 / 已送达模型）；「停止」中断当前回合（已提交的节点不受影响）。
  - **＋ 附件**：「上传文件（cif/hkl/res 等小文件）」存到项目 `uploads/`；「引用原始帧目录…」填本机目录（cbf/sfrm/img/osc/mccd/h5…），检测后插入到输入框，由 `import_frames` 就地读取，不上传。
  - 图片随消息直接发给模型（GLM-5.3 无视觉，Flash 有）；PDF/Word 自动抽文本。
  - 左下 **权限芯片**（显示「自动」等）：点开就是 **设置菜单**（§3）。
  - 右下显示当前模型 · 推理强度。

### 2.3 右栏（晶体窗格）
- **结构卡**（顶部）：节点芯片、分支、非对称单元化学式、空间群、R1/wR2/GooF、分辨率（含 SHEL 工作截断）、Rint、完整度、独立衍射、残峰/残洞、参数数、Flack；「引用」把这组数带进对话。
- **范围菜单**（Olex2 语义）：范围 = 非对称单元（fuse）/ 晶胞（pack cell）/ 超胞 2³ 3³ 4³ / 半径 r Å（以选中原子或 ASU 质心为中心）/ 分数盒；动作 = 长一层（grow -s，可连按到 4 层）/ 长满（grow，直到对称算符重复；周期骨架标"周期截断"）/ 补全（grow -w，让溶剂/抗衡离子跟着长出来）/ 收回（fuse）/ 装配非对称单元…（预填一条让 Agent 调 `assemble_asu` 的请求，会改模型、走审批）。
- **样式**：线框 / 球棍 / 椭球（50 % 热椭球）/ 空间填充。**元素**行按元素显隐（MOF 常用：藏 C、H 只看金属-氧节点）。
- **显示图层**：多面体、标签、无序异色（PART 着色）、Q 峰（差值残峰，点击可引用）、密度图（Fo−Fc 绿缺红多 / 2Fo−Fc 总密度，等值面可调）、孔道（1.2 Å 探针等值面，标体积与电子数）、简化网、对称元素、切片、生长键（点幽灵球长出邻居）、短接触、结构变化（与父节点或对比基线比）、自旋、出版样式、导出图。
- **关系图层**：氢键、π–π、C–H···π、C–H···X、卤键、阴离子–π（每条列判据、对称码、是否满足；边缘伙伴标"范围外"）。
- **测量**：连续点 2/3/4 个原子得距离/角度/二面角；「引用」带进对话。选中原子可「居中」「在对话中引用」。
- **带图提问**：把当前画面截图 + 一句说明（节点/范围/图层）放进输入框。
- **聚焦模式**：右栏扩到 ≥64 %，Esc 还原。
- 页签：
  - **结构**：上面这些。
  - **节点树**：分支折叠、诊断分支默认收起、每节点 R1/wR2/GooF/峰值/参数（"沿用"= 该节点未精修）、「已交付」「树内最佳」「当前」标记；「检出」把请求送进对话（Agent 调 checkout，走审批）；「分支对比」表；「对比」按钮设对比基线。
  - **指标**：数据块（完整度、独立衍射、冗余、空间群、d_min 数据标称 vs 工作截断）、指标趋势、谱系、配位环境（按当前场景统计，跨对称配位键需切到生长模式）。
  - **验证**：checkCIF 警报 A/B/C/G，每条含义/常见原因/常规处理（知识库），「查看逐条解释」读 VALIDATION.md；顶部提示报告来自哪个节点/交付版本；「引用」把警报放进对话问怎么处理。
  - **产物**：顶层交付（final.cif / final.fcf / final.res / SUMMARY.md / VALIDATION.md / checkcif）、运行日志；预览/打开。

### 2.4 项目主页：项目占用与清理（2026-09-16 起）
- 项目主页底部的 **「项目占用」** 卡把项目目录分成四格：**用户数据**（你放进来的 hkl/res/cif、uploads）、**交付件**（`CrystalPilot Results/`）、**系统生成**（`.crystalpilot/` 下的节点库、反射数据版本、SHELXL/SHELXT/checkCIF 作业目录、缓存）、**可回收**。
- 「查看可清理项」只列清单不动文件；「执行清理」逐项复核后才动手，且**只处理未被节点树或交付引用的中间产物**。四类动作：
  1. `job.hkl` 与反射数据版本逐字节相同 → 改为硬链接（内容与路径都不变，只是不再重复占盘）；
  2. 中间 `job.cif` 里内嵌的反射块与 `job.hkl` 相同 → 换成一行引用标记，交付（`write_outputs`、checkCIF）时按原字节恢复；
  3. 未被引用、也不是最近 3 个的作业 → 只删结构因子表 `job.fcf`（`.ins/.res/.lst` 保留，可回溯）；checkCIF 完成后删 PLATON 的 `.ckf/.ps` 等中间产物（`checkcif.json/.chk/.vrf` 报告保留）；
  4. 已完成的输入事务暂存目录（`.staging/*`，大文件均已进反射数据版本）→ 删除。
- 永远不动：用户文件、`nodes/`、`data/`（反射数据版本；版本目录内部只允许把逐字节相同的副本改成硬链接）、`CrystalPilot Results/`。回合运行中按钮会提示"结束后再清理"。
- 实测（test3-2 的副本）：713 MB → 212 MB；剩下的主要是交付件 80 MB、用户数据 28 MB、反射数据版本、被引用作业的 fcf。要再小只能删交付件，系统不会替你做。
- 新作业从 2026-09-16 起直接以硬链接引用反射数据版本，成功后的 `job.cif` 立即去重，所以新项目不会再长到几百 MB。
  - **分析**：相互作用、孔道与堆积（体积、电子数、LCD/PLD、维度、堆积指数）、客体位置（笼内/通道/空腔/间隙）、拓扑与形状（独立网、互穿判定、简化网+RCSR、螺旋、有限片段球形度/最大无弦环）；「结构类别」建议与采用；"对称唯一表 · 整个晶体 · 不随显示范围变"。

## 3. 控制面（输入框上的三处 + 齿轮）

改设置有三个入口，各管一摊：

- **自动 芯片**（输入框左下）：权限模式 + 本项目的几个开关（§3.1、§3.2）。
- **模型按钮**（输入框右下，写着当前模型·档位）：选模型、选推理档位、切提供方（§3.3）。
- **齿轮 → 设置**（左栏底部，或 `/settings`）：提供方与密钥、全局默认、上下文、外观、内核（§3.4）。

还可以在输入框打 `/` 调出命令列表（↑↓ 选择、Tab 补全、回车执行、Esc 取消），命令与 Codex CLI 同名：`/model` `/effort` `/permissions` `/subagents on|off|auto` `/compact` `/context` `/status` `/mcp` `/skills` `/new` `/rename <名称>` `/fork` `/stop` `/settings`。`/status`、`/context`、`/mcp`、`/skills` 会把内核实时状态写成一张对话内的小卡片。

### 3.1 权限模式（回合运行中不能切）

| 模式 | 晶体学工具 | Shell / 文件 | 说明 |
|---|---|---|---|
| **只读** | 只读工具可用，写类工具被拒 | 沙箱只读 | 看结构、问问题；CIF 只读项目默认 |
| **请求批准** | 改模型/写文件的工具先弹审批卡 | 每条命令弹审批卡 | 想逐步把关时用 |
| **自动**（默认） | 全部自动通过 | 工作区内命令自动通过；命中保护区黑名单（`testAPI.txt`、E 盘、codex 状态、kill/taskkill、shutdown/format/reg、git push/remote、往 CrystalPilotData 写）**立即拒绝**并让模型改道 | 无人值守实机格的模式 |
| **完全访问** | 全部自动通过 | 沙箱关闭、全部自动通过 | 不建议 |

「本次会话总是允许」= 同一工具/同类操作本会话内不再问。审批 15 分钟无人处理按拒绝。

### 3.2 项目设置（在 自动 芯片里，鼠标悬停有说明）
长句说明收进了悬停提示，面板只留短标题。
- **允许上传到 IUCr checkCIF**：默认关；开着时 `submit_iucr_checkcif` 仍逐次审批。本地 PLATON checkCIF 不受影响。
- **是否开启子代理？**：一个开关 + 一行状态。开=五个只读审计角色随时可委派、内核提供子代理工具；关=内核不提供。开关旁的"自动"按钮回到自动档：**推理档位为该模型梯子的最高档时开，其他档关**（网关 astra 的最高档是 超高 ultra；OpenRouter GLM 的梯子只有 低/中/高，"高"即最高）。这个开关是"真开关"——它通过进程级 `features.multi_agent` 决定内核是否真的提供子代理工具；改了会在本回合结束后重建引擎（空闲时立即）。R7 A/B 结论：机制可用、无科学收益，默认自动。
- **知识模式**：完整（含专家判断规则，默认）/ 纯工具（只给操作契约，消融对照）。运行中不能切。
- **结构类别**：未声明 / 小分子 / 大环 / 笼 / 周期框架（MOF/COF/HOF）/ 盐-共晶。分析页按它展开区块，Agent 从 `get_project_brief` 读到。
- （**专家子代理**这个实验开关移到了 设置 → 高级。）

### 3.3 模型按钮（输入框右下）
点写着「GPT-6 Astra · 极高 ▾」的按钮，弹出 Codex 式浮层：
- **提供方标签页**：在顶部切 crystalpilot / openrouter（没配密钥的会标一个 `!`）。
- **模型列表**：直接读所连 API 支持的模型（右侧带上下文长度、视觉/纯文本徽章；已登记到内核的打绿点；接口 `/models` 没列出的置灰但仍可选）。有搜索框；底部可填自定义 id。
- **推理档位**：显示**该模型自己的档位**，名称照搬（网关 astra：低/中/高/极高/最高/超高；GLM：低/中/高；没有推理档位的模型这里显示"该模型没有推理档位"）。
- **生效时机**：模型与档位对**下一条消息**生效；提供方在对话开始时固定，所以切提供方后浮层会给出「分叉当前对话」或「新建对话」两个按钮（codex 把 provider 钉在线程上）。

### 3.4 设置面板（齿轮 / `/settings`）
以前要改配置文件或命令行的事，现在都在这里，像别的 API 应用一样：
- **提供方与密钥**：列出 `config.toml` 声明的每个提供方（base URL、密钥状态、更新时间），可**添加/编辑/测试连接/设为默认/删除**，还能一键「当前项目用此提供方」。**密钥只写入本机 `secrets/<id>.txt`，永不回显、不进仓库、不打日志**；测 OpenRouter 会顺带显示额度信息。
- **模型与推理**：改 `config.toml` 的全局默认模型/档位/提供方（对没有单独覆盖的项目生效）。
- **上下文**：全局与本项目的**上下文窗口**和**自动压缩阈值**（token），留空=按模型目录值；内核接近阈值会自动压缩，也能「立即压缩当前对话」。改动在引擎重启后生效（空闲即时、回合中回合末）。

## 6. 已知情况与排障
- **求解含重原子（Zr、Hf、稀土、卤素…）的大胞时「看着一直不动」**：这不是卡住。SHELXT 相位求解通常几十秒就完，但声明了重于 Sc 的元素后它会自动加 `-a`，逐个评估 Laue 类里的全部空间群（六方 6/mmm 是 18 个），在 39 Å 的六方胞上要 10–15 分钟，而且**这一阶段 SHELXT 不输出任何东西**。2026-09-18 两个 NU-1000 项目就是这样：用户在 6 分和 12 分时按了停止，SHELXT 却在停止后10–15 分钟解出了结构，没人看见、也没被采用。现在对话里有「后台求解行」和状态轨提示（见 §2.2），会写出阶段、已用时和本项目先前同类搜索的参考用时；如果空间群已经确定，可以让 Agent 传 `space_group=` 直接跳过搜索（2–4 秒）。已完成但未采用的解，在新回合里让 Agent 执行 `run_shelxt(from_job='<作业名>')` 即可，不必重跑。工具侧也已修正：相位结束后不再把「总用时 ÷ 尝试数」当每次尝试用时；搜索宽限用完时若进程仍在消耗 CPU 会按片延长（最多再 2 × `search_grace_s`），不会把健康的搜索杀掉。
- 若发消息回 **Internal Server Error**：先看 `workdir/uvicorn_r13.err.log` 末尾。2026-09-07 出现过一次，在模型菜单里点过的某些模型（Claude / GPT-5.1 / GLM-Flash）把 OpenRouter 的 `file`/`video` 输入类型写进了内核模型目录，codex 只认 `text/image/audio`，导致它**加载配置就失败**、所有项目都发不出消息。已修（写入前过滤），若再遇到类似「codex 加载配置失败」，可删掉 `codex-home/model_catalog.custom.json` 里可疑的条目再重启服务器。
- 网关 gpt-6-astra 暂不可用；GLM 偶尔漏带工具命名空间或"只宣布不调用"，系统会提示它重发；结果差不一定是系统问题，可能是基模。
- 「晶体学工具服务失联」横幅 → 点「重启引擎」（回合运行中要等结束）。
- **8010 打不开 / 服务像凭空消失了**：先看端口上还有没有人监听（`netstat -ano | findstr :8010`）。2026-09-07 遇到的是最难查的一种，**进程还活着、应用也正常，但端口上没有人在监听**：Windows 的 Proactor 事件循环只要碰上一次 accept 失败（WinError 64「指定的网络名不再可用」，客户端在连接建立途中断开就会触发），asyncio 就会顺手**把监听套接字关掉**，而 uvicorn 不会因此退出，于是既没有崩溃、也没有退出码，健康检查更是无从查起。唯一的痕迹是 `workdir/uvicorn_r13.err.log` 末尾的 `Accept failed on a socket`。已修：重启脚本改用 selector 事件循环（`--loop asyncio:SelectorEventLoop`），它把同一件事当成普通的连接中止、继续监听（2026-09-05 19:55 那次「服务器不明原因消失」几乎可以肯定也是它）。
- 其余打不开的情况仍用 §1 的重启脚本；改了 Python 代码也要重启；改了 UI 要 `npm run build`。
- **打开项目要几分钟、或内核起不来（`failed to initialize sqlite state runtime`）**：2026-09-16 查到根因是 codex 内核把自己的每一行日志都写进 `codex-home/logs_2.sqlite`（三周长到 1.6 GB，引擎运行时每分钟约 15 MB），写前日志一大，下一次启动就卡在 sqlite 上。CrystalPilot 不读这个文件；重启脚本（Windows `restart_server.ps1`、Linux `server_linux.py`）现在会在它超过 256 MB 且没有本仓库的 codex 进程时把它删掉，内核会重建。切勿在内核运行时用 sqlite 工具打开 codex-home 下的任何数据库。
- 同一时刻两次「打开项目」（例如两个标签页）曾让第二个内核启动失败：已改为同路径的并发打开等第一个建好再复用。
- **2026-09-08 起，旧项目的反射计算会先被拒绝**（"Historical reflection data is unknown; bind matching HKL explicitly"）：09-08 之前建的项目，其节点没有记录"是用哪一版反射数据算出来的"，所以看几何、分析页签、引用都正常，但精修 / 掩膜 / SHELXL / 孪晶 等一切要用反射的工具都会拒绝，直到在对话里让它执行一次 `swap_reflection_data(model_node=<当前节点>, hkl="crystal.hkl", reason="绑定本项目自己的数据")`，这会生成一个新的已绑定子节点，旧节点和旧指标不改写。系统在 `get_project_brief` 里也会把这句话直接告诉模型。这是 09-08 那轮"反射数据版本"设计的一部分（`docs/UPGRADE-2026-09-08-workbench.md` §11），不是故障。
- 服务器重启后，浏览器里**已经开着的页面不用再刷新**：项目实时通道原先会在服务器刚起来的那几秒收到 `400 项目未打开` 而永久断开（EventSource 只在网络中断后自己重连，收到非 2xx 就彻底放弃），页面看着一切正常，却不再收到设置 / 审批 / 改名 / 忙碌状态的推送。现在会自动重新打开项目并接回来。
- 左栏里的 `r6-mof-ask*`、`_probe/*`、`ui-import-*` 是测试留下的项目，可「隐藏」。
- **左栏的项目文件夹可以展开/折叠**（点文件夹名即可）：展开后直接看到该项目下的所有对话，点其中一条就切过去；想切到某个项目主页开新对话，鼠标悬停该文件夹点「打开」。
- 之前「在项目 A 的对话里点项目 B 会让晶体窗格报错」已修：根因是 3Dmol 全页面共用一块离屏画布，旧视图被拆掉时把它留成 0×0，下一帧就抛 `transferToImageBitmap` 失败。现在画不出来的那一帧会被丢掉（并记进诊断），不再连累整个窗格；同时点文件夹只展开、不再切项目。
- 「新对话」= 在**当前打开的项目**里开新线程（项目主页会写明“新对话将创建在 …”，可「更换项目」）；没有打开项目时会先让你选项目。
- 三次蓝屏都是内存类错误（最近 0x12b），建议跑 memtest。
